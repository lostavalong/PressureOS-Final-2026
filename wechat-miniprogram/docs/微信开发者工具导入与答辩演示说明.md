# PressureOS 微信小程序导入与答辩演示说明

## 一、当前版本结论

本工程已经具备可演示的小程序前端与完整 Mock 业务闭环，可直接导入微信开发者工具，不需要 npm 安装或编译脚本。

当前版本默认使用 `mock` 模式，能够独立演示：

- 实时压力、温度、趋势与设备状态；
- 任务列表、新建、删除、自动保存与恢复；
- 从模板创建任务；
- 数据采集、逐点删除、线性拟合、残差与不确定度；
- 模板 JSON 导入；
- 设备配对和连接诊断的交互流程。

尚未接入树莓派真实 REST/WSS 接口，因此答辩时应称为“微信小程序交互原型或移动端扩展验证”，不能称为已经完成真机无线联调。

## 二、导入步骤

1. 从微信官方渠道安装最新版“微信开发者工具（稳定版）”。
2. 打开开发者工具并使用微信扫码登录。
3. 选择“导入项目”。
4. 项目目录选择解压后的 `PressureOS_WeChat_MiniProgram` 文件夹。
5. 仅在电脑模拟器演示时，可选择测试号或无 AppID 模式；工程当前的 `project.config.json` 使用 `touristappid`。
6. 若需要手机预览、体验版或上传代码，应填写已经注册的小程序真实 AppID，并确保当前微信号是该小程序的管理员或开发者。
7. 导入后点击“编译”，首页会自动产生 10 Hz Mock 压力数据。

## 三、推荐答辩演示路径

1. 在“仪表”页展示压力、温度和实时趋势。
2. 进入“任务”，打开已有任务，展示任务状态与自动恢复。
3. 新建一个任务，自定义任务名称和目标点数。
4. 在记录页填写外部变量并连续采集至少 3 个点。
5. 进入分析页，展示拟合方程、R²、残差和不确定度。
6. 展示模板库的 JSON 导入入口和设备配对页。

建议全程使用 Mock 模式，避免答辩现场网络、合法域名或树莓派接口状态影响演示。

## 四、是否需要微信审核

- 开发者工具模拟器：不需要审核。
- 点击“预览”后由项目开发成员扫码测试：不需要公开发布审核。
- 上传为开发版或设置为体验版，供已绑定的开发者、体验成员使用：不需要公开发布审核。
- 正式发布给普通微信用户搜索和使用：需要提交微信平台审核。

正式发布的审核耗时不固定，应至少预留 1—7 个工作日，并考虑驳回后修改重提的时间。首次公开发布还可能涉及小程序备案、服务类目、隐私保护指引、用户信息处理说明、合法 HTTPS/WSS 域名和证书等前置工作。

因此，若只用于近期答辩，采用开发者工具或体验版即可，不需要等待正式审核。

## 五、切换真实设备前还需完成

1. 将 `config/env.js` 的 `mode` 从 `mock` 改为 `live`。
2. 确认树莓派 REST API 与 WebSocket 数据结构符合 `docs/树莓派API对接表.md`。
3. 决定局域网直连、设备热点或云端中继的通信架构。
4. 正式版配置受信任的 HTTPS/WSS 域名与证书；不能依赖关闭域名校验。
5. 完成一次性配对、短期令牌、权限控制、断线重连、限流和审计。
6. 在 Android 与 iOS 真机分别验证网络、蓝牙权限和后台切换行为。

## 六、当前静态验收结果

- 15 个 JSON 配置文件均可正常解析；
- 23 个 JavaScript 文件均通过语法检查；
- 7 个页面的 JS、JSON、WXML、WXSS 文件全部齐全；
- Mock 模式已验证任务读取、任务创建、采点、拟合、报告产物和任务删除闭环。
