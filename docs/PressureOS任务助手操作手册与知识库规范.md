# PressureOS 任务助手操作手册与知识库规范

版本：1.0  
适用范围：PressureOS 树莓派端、任务模板、小程序后续接入及现场演示

## 1. 助手定位

PressureOS 助手是“测量任务副驾驶”，不是不受约束的通用聊天机器人。它必须首先理解当前页面、当前任务阶段、测量数据、串口状态、安全状态和分析结果，再回答用户问题。

每条核心建议必须回答四件事：

1. 当前发生了什么；
2. 为什么会出现这种状态；
3. 推荐用户下一步怎么做；
4. 能否提供一个经过白名单校验的一键操作。

助手必须离线完成安全判断、任务流程引导和常见故障解释。云端模型以后只能用于更自然的表达和资料检索，不能绕过本地安全逻辑直接修改参数或控制硬件。

## 2. 用户交互层级

### 2.1 导航栏状态点

- 红色：保护触发或其他必须立即处理的风险；
- 橙色：串口中断、标定不可信、异常点待复核等阻断问题；
- 蓝色：当前有任务下一步建议；
- 绿色：当前状态正常或阶段已经完成。

### 2.2 主动建议卡

页面或任务阶段发生重要变化时，系统显示短时建议卡。建议卡只显示状态标题和一句摘要，点击后展开完整助手。普通卡可关闭，保护触发类红色卡不可通过普通关闭消除。

### 2.3 助手面板

助手面板包含：

- 当前页面或任务上下文；
- 当前最高优先级建议；
- “为什么”解释；
- 一个主要操作按钮；
- 随页面和阶段变化的快捷问题；
- 本任务最近助手记录；
- 本地关键词问答输入框。

触摸屏上应优先使用快捷问题，减少键盘输入。用户输入的问题由本地知识库关键词检索，不匹配时明确说明能力边界，不生成未知硬件参数。

## 3. 决策优先级

助手每次只突出当前最高优先级事项：

| 优先级 | 类别 | 典型条件 | 行为 |
| --- | --- | --- | --- |
| P0 | 安全警报 | 保护锁存、量程极限、数据库不可用 | 中断普通流程，要求先处理风险 |
| P1 | 流程阻断 | 串口断开、数据超时、标定不可信、异常点待复核 | 解释原因并进入诊断或复核 |
| P2 | 任务下一步 | 准备完成、可以采点、可以分析、可以导出 | 提供单一主要操作 |
| P3 | 使用技巧 | 页面说明、模板说明、普通状态 | 不打断用户工作 |

安全提示不得被普通建议覆盖。软件量程保护不能被描述为最终硬件安全闭环。

## 4. 任务五阶段完整操作流程

### 4.1 第 1 阶段：了解任务

目标：让用户在操作前理解测量目的、输入变量、准备条件、流程和安全边界。

助手应显示：

- 本次任务名称及所用模板；
- 实验目标和自变量/因变量；
- 模板的五步工作流；
- 当前模板准备清单；
- 当前模板安全说明；
- 是否需要零点校正、预热或标准器。

允许的一键操作：`开始测量阶段`。

阻断条件：数据库不可写、保护锁存、真实硬件数据链路异常。若只是 Wi-Fi 或蓝牙离线，但任务完全依赖本地串口，应说明影响而不是无条件阻断。

用户常问：

- 这个实验要做什么？
- 开始前需要准备什么？
- 为什么要归零？
- 归零和标定有什么区别？
- 当前模板需要几个点？

### 4.2 第 2 阶段：数据记录

目标：逐点获得可追溯、稳定并且量程安全的数据。

每次采点前助手按顺序检查：

1. 数据库可以写入；
2. 真实硬件串口已连接且数据新鲜；
3. 换算、零点和标定处于可信状态；
4. 压力没有进入警告或保护区；
5. 读数满足稳定窗口要求；
6. 横轴变量已填写且数值合法；
7. 测点数量未超过任务上限。

采集成功后系统立即写入 SQLite，更新任务最后编辑时间并重算基础统计。用户不需要手动保存。

误测处理：

- 明确选择对应数据点；
- 删除前确认点号和横轴值；
- 删除后自动重新编号和计算；
- 助手记录“人工删除”，不得暗示系统自动清洗；
- 若异常原因不确定，优先保留并重测，而不是直接删除。

任务切换：每个任务保存独立测点、阶段和助手历史。用户切换后再次进入，应恢复到上次阶段。

用户常问：

- 当前读数可以采集吗？
- 为什么一直不稳定？
- 采错了怎么办？
- 退出页面会不会丢失？
- 为什么还不能进入分析？

### 4.3 第 3 阶段：数据处理

目标：说明系统执行了什么计算，并提醒用户检查模型前提。

当前基础实现使用普通最小二乘法拟合 `p = ax + b`，计算：

- 斜率和截距；
- Pearson R；
- 决定系数 R²；
- 每点残差；
- 残差标准差和最大绝对残差；
- 粗大误差嫌疑点预筛；
- A 类、B 类、合成和扩展不确定度演示值。

助手必须明确：

- 两个点虽然可以确定一条直线，但不能评估残差，因此基础分析至少需要三个点；
- R² 高不等于实验一定正确；
- 多点标定、零点漂移和泄漏测试具有各自专业判据，当前线性模型只是基础工具；
- 正式不确定度预算还需纳入标准器、证书、环境和方法分量。

允许的一键操作：`查看结果解释`；数据不足时只能返回补充数据。

### 4.4 第 4 阶段：结果分析

目标：让用户理解结果并完成有依据的人工确认。

推荐审核顺序：

1. 检查关系式是否符合物理预期；
2. 检查斜率、截距和单位；
3. 查看 R²，但不单独依据 R²；
4. 查看残差是否随机分布；
5. 查看异常点是否需要复测；
6. 查看不确定度口径是否完整；
7. 确认实验条件没有中途改变。

异常点策略：标准化残差只用于“嫌疑点”提示。助手不得自动删除，不得将统计提示直接表述为粗大误差结论。用户应检查录入、稳定性、装置扰动和工况，再选择保留、删除或重测并记录原因。

允许的一键操作：

- 有异常或模型明显不适用：`返回核对数据`；
- 条件满足：`确认并进入导出`。

### 4.5 第 5 阶段：导出归档

目标：生成可复核、可继续处理、可用于报告的任务产物。

标准数据包包括：

- CSV：横轴、压力、来源和时间；
- JSON：模型、R/R²、残差、不确定度和异常点摘要；
- SVG：可缩放拟合图。

导出不会删除任务。再次导出会生成新的时间目录。正式复测建议创建新任务，保留旧任务和旧数据包作为证据。

## 5. 模板专项引导

### 5.1 压力—质量关系实验

- 准备：确认质量值来源，检查无载荷零点；
- 采集：缓慢加载，每次稳定后采点；
- 分析：重点查看斜率、截距、残差随机性和不确定度。

### 5.2 多点压力标定

- 准备：冻结量程、标准点、上/下降行程和标准器信息；
- 采集：按既定顺序逼近，不随意跳点；
- 分析：除线性拟合外，正式版本还要评价示值误差、重复性和回程误差。

### 5.3 零点漂移观察

- 准备：完全卸压、连通大气、充分预热；
- 采集：固定时间间隔，避免触碰和快速温变；
- 分析：关注零点极差、趋势斜率、标准差和温度同步变化。

### 5.4 定压泄漏测试

- 准备：确认管路额定压力和泄压通道；
- 采集：达到目标压力、隔离压力源后开始计时；
- 分析：关注压力—时间斜率、快速压降异常和模板判据。

### 5.5 快速空白任务

- 自动编号适合仅需连续记录压力的场景；
- 自定义横轴适合质量、时间、位移等外部变量；
- 三个点只满足基础拟合最低条件；
- 若残差呈明显结构，应更换模型或导出后进行专业处理。

## 6. 安全边界和动作白名单

助手可以直接执行：

- 页面导航；
- 打开当前任务；
- 从说明阶段进入采集；
- 在满足点数条件后结束测量；
- 打开分析页；
- 人工确认分析后进入导出；
- 生成任务数据包；
- 刷新无线只读状态；
- 请求串口重新检测。

助手不能直接执行：

- 自动删除测点；
- 在有载或不稳定状态下归零；
- 写入标定或温补系数；
- 自动确认粗大误差；
- 绕过量程保护继续采集；
- 直接解除硬件保护锁存；
- 未经回读确认控制阀、继电器或压力源。

涉及参数写入、归零、联锁复位和硬件控制的正式版本必须增加条件检查、二次确认、设备回读和审计记录。

## 7. 故障排查口径

### 7.1 串口无数据

依次检查供电、USB/CP2102N、Linux 端口与权限、115200/8N1、换行格式、协议合法帧、最后帧年龄、CRC 和丢帧。不要在尚未确认原始帧连续时先调整压力换算公式。

### 7.2 读数不稳定

检查压力源脉动、泄漏、管路触碰、装置振动、温变和滤波方式。助手只说明软件稳定窗口，不应把滤波后的平滑外观等同于真实稳定。

### 7.3 数据显示但不能采集

常见原因包括真实数据不新鲜、标定未验收、量程进入警告区、稳定条件不满足或横轴输入无效。助手应逐项列出当前状态，不使用笼统的“系统异常”。

### 7.4 数据库异常

暂停正式任务，执行数据库完整性、写入回读和剩余空间检查。程序运行期间不得手工删除 SQLite、WAL 或 SHM 文件。

## 8. 机器可读知识库规范

知识库文件：`data/assistant/knowledge_base.json`。

每个条目至少包含：

```json
{
  "id": "measurement_stability",
  "title": "为什么要等待读数稳定",
  "summary": "一句摘要",
  "body": "完整回答",
  "bullets": ["操作步骤或判断依据"],
  "caution": "可选风险说明",
  "actionId": "open_measurement",
  "actionText": "查看实时测量",
  "source": "操作手册章节",
  "keywords": ["不稳定", "波动", "峰峰值"]
}
```

规则：

- `id` 一经发布不得随意修改；
- `actionId` 必须存在于本地动作白名单；
- 安全说明必须引用当前项目已经确认的边界；
- 未确认硬件参数不得写入知识库；
- 动态数值由 C++ 上下文填充，不能写死在静态文案中；
- 新模板应增加 `templateGuides`，说明准备、采集和分析重点。

## 9. 模板助手字段建议

```json
{
  "assistantGuidance": {
    "preparationChecklist": [],
    "blockingConditions": [],
    "analysisExplanations": [],
    "troubleshooting": []
  }
}
```

工作流步骤可使用 `assistantArticle` 引用知识条目。模板导入通过结构校验不代表实验方法已经审核，正式使用前必须用模拟数据和真实工况分别验收。

## 10. 验收标准

1. 无网络时，任务下一步、安全提示和常见问答仍可工作；
2. 任务五个阶段都有不同的快捷问题和主要建议；
3. 串口断开、数据超时、量程警告和保护锁存优先于普通流程；
4. 助手按钮能进入正确页面或阶段，而不是只弹出文案；
5. 不允许通过助手自动删除数据、写标定参数或复位保护；
6. 每个任务保存独立助手问答和操作记录；
7. 任务切换后建议和快捷问题在 1 秒内更新；
8. 1024×600 触摸屏上文字无溢出，主要按钮触控高度不小于 44 px；
9. 知识库无法匹配时明确说明范围，不生成虚构答案；
10. 所有助手直接操作写入审计日志。

## 11. 维护流程

新增功能时按以下顺序更新：

1. 明确真实状态来源和信号；
2. 在上下文服务中增加字段；
3. 在规则引擎中定义优先级与触发条件；
4. 在动作分发器中评估是否可进入白名单；
5. 更新知识库条目及本手册；
6. 增加后端测试和 1024×600 截图验收；
7. 在树莓派真实串口模式下验证；
8. 再考虑是否向小程序或云端模型开放。
