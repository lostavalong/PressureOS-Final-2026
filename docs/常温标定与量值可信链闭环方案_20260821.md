# PressureOS 常温标定与量值可信链闭环方案

版本：1.0（2026-08-21）  
适用对象：STM32F103 + AD7124-8 下位机、树莓派 PressureOS、项目常温现场试验

## 1. 结论先行

项目已经完成“数据能传到树莓派”的协议基础，但“树莓派上的压力值可以作为正式量值使用”还没有完成验收。当前决策如下：

1. 暂不进行跨温区温度补偿。温度通道保留，用于界面监测、任务记录和异常环境提示，不参与压力换算。
2. STM32 继续使用已实机验证的 V1.0.3 固件，不改动已稳定工作的 ADC 和 LCD 驱动。该固件提供 CRC16、帧序号、状态位和 `GET_INFO`。
3. PressureOS 中的压力示值采用“常温标定换算值 → 所选滤波 → 零点偏移”的单一路径，不再叠加演示温补项。
4. 在常温多点标定、判据审核、参数固化和上下位机对照完成前，真实硬件模式保持“仅供联调”，不得设置 `PRESSUREOS_VALUE_TRUSTED=1`。
5. 软件量程提示不是最终安全保护。过压切断、泄压和失效安全仍必须由 STM32/独立硬件链路承担并单独验收。

补充说明：量值可信状态未开启时，零点漂移观察和多点压力标定任务仍必须能够采集，否则无法形成验收所需数据。此类点统一标记为“工程记录”，只用于零点、漂移和标定分析；普通正式测量任务仍保持阻断。

## 3. 标定前必须冻结的信息

标定开始前，由项目负责人、硬件负责人和软件负责人共同填写并签字确认。任何一项为空，都不能把参数标记为“正式”。

| 信息 | 待确认内容 |
| --- | --- |
| 设备编号 | 树莓派整机/压力表唯一编号 |
| 传感器编号 | 压力传感器型号、序列号、灵敏度或出厂资料 |
| 下位机版本 | 固件版本、构建时间、源代码提交或压缩包校验值 |
| 压力类型 | 表压、绝压或差压；零点的物理定义 |
| 正式量程 | 例如 `0～600 kPa`；只有具备可靠负压标准源时才验收 `−100～0 kPa` |
| 显示分辨力 | 当前界面候选值为 `0.1 kPa`，需与传感器能力和项目要求确认 |
| 标准器 | 名称、型号、编号、证书编号、有效期、准确度等级/最大允许误差 |
| 允许误差 | 项目对示值误差的明确上限，不能由软件自行假定 |
| 重复性判据 | 同一点重复测量允许的最大极差或标准差 |
| 回程误差判据 | 同一点升程与降程示值差的允许上限 |
| 稳定判据 | 稳定等待时间、窗口长度、峰峰值或变化率阈值 |
| 环境范围 | 本次常温标定允许的温度和变化范围；温度只记录不补偿 |

若目前没有可追溯的负压标准源，正式可信量程先限定为 `0～600 kPa`。界面可以保留负压趋势显示，但报告不得宣称 `−100～600 kPa` 全量程均已标定。

## 4. 现场准备

### 4.1 设备与连接

- 标准压力源或压力控制器与被检压力端可靠连接，接头、管路和密封件适配量程。
- 确认介质、管路和传感器兼容，排除堵塞、明显泄漏和残余压力。
- STM32、树莓派和显示屏使用稳定电源；USB 串口和 ST-Link 线缆固定，避免试验中松动。
- 下位机 LCD 与 PressureOS 同时可见，以便逐点对照。
- 在 PressureOS 设备页确认：V1 协议、固件 1.0.3、有效帧持续增加、CRC 错误不增加、帧序号连续。

### 4.2 预热与零压

1. 按传感器和标准器要求预热；没有明确要求时，项目组应先确定统一时间并记录，不能每次随意变化。
2. 压力端完全卸压并连通其零点参考环境。
3. 观察标准器、STM32 LCD 和 PressureOS 至稳定。
4. 记录零点原始码、PressureOS 未归零示值、环境温度和稳定性指标。
5. 零点偏移超出项目预设上限时停止试验，检查管路残压、供电、接线和传感器状态，不能直接用软件归零掩盖故障。

## 5. 推荐标定路径

### 5.1 正压量程 `0～600 kPa`

建议至少使用以下六个点：

`0、120、240、360、480、600 kPa`

完整次序建议为：

`0 → 120 → 240 → 360 → 480 → 600 → 480 → 360 → 240 → 120 → 0`

每个点应执行：

1. 缓慢接近目标点，避免明显过冲。
2. 等待标准器和被检表示值满足已冻结的稳定判据。
3. 记录标准压力、压力原始码、STM32 LCD、PressureOS 原始/滤波示值、温度、序号、状态位和时间。
4. 每点至少采集三次独立稳定结果；若项目标准要求更多次数，以项目标准为准。
5. 对异常点只允许“标记并说明后重测”，不得无痕删除。

为评价重复性，建议至少再完整执行一轮升程和降程。正式次数最终由项目允许误差和所采用的计量规范决定。

### 5.2 负压段（条件项）

只有具备可靠负压标准器和适配管路时，才执行例如：

`0 → −20 → −40 → −60 → −80 → −100 → −80 → −60 → −40 → −20 → 0 kPa`

没有负压标准条件时，本段标记为“未验收”，不得通过正压拟合外推得到负压可信结论。

## 6. 数据计算与判定

以下计算由 PressureOS 标定任务生成，但最终判定必须使用第 3 节事先冻结的阈值。

### 6.1 示值误差

对每个点：

`示值误差 e_i = 被检表示值 P_i − 标准器示值 P_ref,i`

同时保留绝对误差和相对满量程误差。接近零点时不宜只看相对读数百分比。

### 6.2 线性模型与残差

若项目采用线性换算：

`P = a × Raw + b`

其中 `Raw` 为 AD7124 压力通道原始码，`a` 为比例系数，`b` 为截距。每一点残差为：

`r_i = P_ref,i − (a × Raw_i + b)`

软件应保存拟合系数、R²、每点残差和原始数据，不能只保存最终公式。若残差呈明显曲线趋势，应先检查硬件、参考模型和数据质量；是否改用分段或高阶模型必须经过评审，不能为追求更高 R² 随意增加阶数。

### 6.3 重复性

同一标准点多次读数可计算极差或实验标准差。推荐同时保留：

- 极差：`R_i = max(P_i) − min(P_i)`；
- 样本标准差：`s_i`；
- 原始次数和被标记的异常记录。

### 6.4 回程误差

同一标准点的升程与降程差：

`H_i = |P_up,i − P_down,i|`

取各点最大值作为重点验收结果之一。不能用单向升程数据代替回程检查。

### 6.5 回零与漂移

完成最高压力点并返回零压后，记录末次零点与初始零点之差。若超限，应检查残压、机械滞后、泄漏、供电漂移和传感器状态，再决定是否重做整轮标定。

### 6.6 粗大误差处理

- 软件可以根据残差、稳定性或统计规则提示“可疑点”，但不得自动删除。
- 操作者必须查看原始码、标准器读数、压力是否稳定、是否过冲及操作记录。
- 删除或排除必须填写原因，保留原记录、操作者和时间。
- 若异常可由操作失误确认，应在相同条件下重测；原因不明时不得用重测值覆盖原值。

## 7. 参数固化和版本追溯

验收通过后生成只增不改的参数版本，至少包含：

- `deviceId`、`sensorId`、压力类型和可信量程；
- 固件版本、上位机版本、协议版本；
- 标定日期、操作者、审核者和环境温度范围；
- 标准器信息及证书有效期；
- 原始标定点、拟合方法、系数、残差和统计结果；
- 允许误差、重复性、回程误差和回零判据；
- 参数文件 CRC/SHA-256；
- 生效时间、失效/复核时间和替代版本关系。

参数更新必须执行：二次确认 → 写入 → 回读 → 校验值比对 → 审计记录。旧版本不得覆盖删除。

## 8. 上下位机一致性对照

在零点、中间点和接近满量程点至少各做一次对照：

1. STM32 LCD 与 PressureOS 使用相同压力类型、单位和标定参数版本。
2. 两端采样时间尽量对应，避免在压力变化过程中比较不同瞬间。
3. 记录两端示值差；允许差值必须在试验前确定，至少应考虑两端显示舍入和滤波延迟。
4. 若 LCD 和 PressureOS 长期有固定偏差，先核对零点/截距；若偏差随压力放大，先核对比例系数和 PGA/参考电压配置。
5. 对照不通过时，量值可信状态保持关闭。

## 9. 协议与数据链验收

在稳定供电和固定压力下进行连续运行测试，并保存统计：

- `GET_INFO` 返回固件 `1.0.3` 和正确设备信息；
- 测量帧 CRC 校验通过，人工构造坏帧能够被拒绝；
- 序号连续性统计正常，出现丢帧时能够计数并提示；
- 拔插串口后能够进入“数据过期”，重连后自动恢复；
- STM32 复位后，上位机识别序号重启/设备信息并恢复采集；
- 状态位异常不会被当成普通有效测量静默写入正式任务；
- 正式任务采点时，数据必须新鲜、CRC 有效、标定可信且满足稳定条件。
- 零点漂移和多点标定任务在标定可信状态开启前可以采集工程记录，但仍要求压力帧新鲜、V1 CRC/序号有效、读数稳定且安全联锁未触发。

建议至少完成 30 分钟连续联调；正式项目如有更长稳定性要求，按项目要求执行。

## 10. 启用量值可信状态

只有以下项目全部通过，才允许在树莓派应用启动环境中设置：

```text
PRESSUREOS_VALUE_TRUSTED=1
```

启用清单：

- [ ] 设备、传感器、压力类型和可信量程已冻结；
- [ ] 标准器资料有效且适配本量程；
- [ ] 零点、升程、降程和重复性数据完整；
- [ ] 示值误差、残差、重复性、回程误差和回零全部符合已签字判据；
- [ ] 参数版本与校验值已固化，写入后回读一致；
- [ ] STM32 LCD 与 PressureOS 对照通过；
- [ ] V1 协议 CRC、序号、状态位、断线与复位恢复通过；
- [ ] 硬件过压联锁完成独立验证；
- [ ] 审核人批准将本参数版本用于正式任务。

任一项失败，都应删除或保持该环境变量未设置，使界面继续显示“仅供联调”。不得为了让自检变绿而绕过验收。

## 11. 温度方案的边界

“不做温补”不等于“不记录温度”。当前必须保留：

- 每个标定点和任务点的环境温度；
- 标定期间的最低、最高和变化范围；
- 温度通道异常/断线状态；
- 参数版本适用的常温环境声明。

如果以后发现同一压力在日常温度变化下出现不可接受的系统性偏差，再单独立项进行多温点试验、模型选择和交叉验证。在没有温箱数据前，不恢复任何经验温补系数。

## 12. 现场最短执行顺序

1. 先在设备页确认 V1.0.3、CRC 和帧序号正常。
2. 填完第 3 节信息，尤其是压力类型、可信量程和误差判据。
3. 预热、完全卸压、记录初始零点。
4. 从模板库创建“多点压力标定”任务。
5. 按升程/降程逐点稳定采集，并完成至少一轮重复。
6. 审核示值误差、残差、重复性、回程误差和回零。
7. 固化参数版本与校验值，回读并核对 LCD。
8. 完成协议连续运行和硬件联锁测试。
9. 审核签字后再启用 `PRESSUREOS_VALUE_TRUSTED=1`。
