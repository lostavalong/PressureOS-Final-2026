# PressureOS 串口接口联调说明与 V1 协议建议

> 文档版本：0.1  
> 编写日期：2026-08-13  
> 适用对象：串口/树莓派软件负责人、STM32 嵌入式负责人、PressureOS 后端负责人  
> 当前状态：V0 现状已经过实机只读验证；V1 为双方评审后冻结的建议方案  
> 安全说明：本文中的串口链路用于测量数据传输。超压切断等最终安全保护不能只依赖树莓派或界面程序。

## 1. 先给结论

1. 树莓派已经能够通过 USB 串口稳定识别下位机，物理链路和基本串口参数已经确认，不需要为了串口通信修改 PCB。
2. 当前 STM32 程序足够支持“临时读取真实 ADC 数据并替换 Demo 模拟数据”，串口同学可以立即开始 V0 兼容接入。
3. 正式项目不建议长期沿用当前格式。嵌入式程序需要修改，重点解决：没有显式通道号、没有等待新一轮 DRDY、重复发送旧值、调试文本与数据混流、没有序号/状态/CRC，以及归零命令未确认当前通道等问题。
4. 建议软件先同时支持两种协议：
   - **V0 兼容模式**：读取当前“纯数字 + CRLF”数据，供立即联调。
   - **V1 正式模式**：读取带协议版本、成对压力/温度原始值、序号、设备时间、状态位和 CRC 的结构化帧。
5. STM32 继续上传原始 ADC 码和硬件状态；标定曲线、软件滤波、温度补偿、单位换算和数据追溯原则上由树莓派统一完成。MCU 内可保留显示和硬件保护所需计算，但不应成为树莓派正式结果的唯一来源。

## 2. 系统链路与职责边界

```text
压力传感器 / 温度传感器
          ↓ 模拟信号
       AD7124-8
          ↓ SPI
     STM32F103RC
  采样、通道识别、状态诊断、硬件安全保护
          ↓ USART1：PA9(TX) / PA10(RX)，115200 8N1
       CP2102N
          ↓ USB
      Raspberry Pi
  QSerialPort → 接收缓存 → 协议解析 → 样本映射
          ↓
  滤波/标定/温补 → SQLite → Qt/QML 页面与任务系统
```

职责边界：

- **嵌入式端**：保证每个上报值确实来自一次完成的新转换，提供明确通道或成对数据、状态、序号和校验；独立承担硬件级故障与安全保护。
- **串口软件端**：设备发现、端口打开、收发、半包/粘包处理、CRC、超时、重连、协议兼容、统计和统一样本输出。
- **PressureOS 数据端**：标定参数版本、滤波、温补、任务记录、数据库、分析和报告。
- **QML 页面**：只显示状态和结果，不直接持有或操作串口对象。

| 项目 | 当前实测值 |
|---|---|
| USB 转串口芯片 | Silicon Labs CP2102N |
| VID | `0x10C4` |
| PID | `0xEA60` |

## 4. 当前 V0 协议：实机现状

### 4.1 测量数据帧

当前下位机持续输出一个无符号十进制 ADC 原始码，每行一个数：

```text
<adc_raw>\r\n
```

示例实测数据：

```text
491160\r\n
491160\r\n
9514489\r\n
9514489\r\n
```

原始字节示例：

```text
34 39 31 31 36 30 0D 0A             -> 491160\r\n
39 35 31 34 34 38 39 0D 0A          -> 9514489\r\n
```

合法 ADC 范围应检查为 `0～16777215`（24 bit）。V0 中没有符号位、单位、帧头、长度、序号、时间戳或 CRC。

### 4.2 当前通道判定方法

STM32 当前代码用数值阈值猜测通道：

| 条件 | 当前代码含义 | AD7124 输入 |
|---|---|---|
| `adc_raw < 8000000` | 压力 | AIN13 - AIN12，Setup0 |
| `adc_raw >= 8000000` | 温度 | AIN5 - AIN4，Setup1 |

实机连续 10 秒只读抓取结果：

| 指标 | 实测结果 |
|---|---|
| 总行数 | 243 |
| 平均串口行速率 | 约 24.3 行/秒 |
| 压力原始码 | `490947～491009` |
| 温度原始码 | `9514422～9514455` |
| 压力侧不同数值 | 12 个 |
| 温度侧不同数值 | 12 个 |
| 单个相同值最大连续重复 | 33 次 |
| 短突发中的相邻行间隔 | 约 3 ms |
| 观察到的较长间隔 | 约 460 ms |

因此，当前的每一行不等于一次新的 ADC 转换。接收端不能把约 3 ms 的串口发送间隔误认为约 333 Hz 的有效测量采样率。

### 4.3 启动与调试文本

STM32 启动时还会发送：

```text
ID = 0xXX\r\n
```

如果以后启用已有的等待超时函数，还可能出现：

```text
DRDY is not ready,ADC is time out!\r\n
```

这些都与测量数据共用同一串口。V0 解析器必须识别并分类为诊断消息，不能把非数字行当作测量值，也不能因为一行解析失败而停止整个接收线程。

### 4.4 当前归零命令

下位机当前只实现了一个接收命令：单字节小写 `z` 或大写 `Z`。

```text
上位机 -> STM32：z
STM32 -> 上位机：Zero set! pa_zero = <value>\r\n
```

当前实现存在以下限制：

1. 命令没有帧头、命令编号、CRC、ACK/NACK 或超时定义。
2. 收到 `z` 后立即读取一次 ADC 数据寄存器，没有确认当时是否为压力通道。
3. 没有等待 DRDY，也没有进行多点平均和稳定性判断。
4. `pa_zero` 只影响 MCU 内部压力计算和本机 LCD 显示；串口仍然发送原始 ADC 数字。
5. 若串口程序自动重试，可能重复执行有副作用的归零操作。

因此，在归零参考状态、表压/绝压定义和嵌入式安全条件确认前，**PressureOS 不应直接向当前固件发送 `z`**。目前界面中的零点漂移校正应继续由树莓派侧做引导、条件检查和可追溯的软件偏移。

### 4.5 当前换算公式，仅供联调核对

STM32 当前压力计算式：

```text
P = 3.3631e-13 × raw² + 0.00020807 × raw - 102.2342 - pa_zero
```

温度换算逻辑：

```text
Vout = ((raw / 8388608) - 1) / 4 × 0.66
R    = Vout / 200 × 1000000
T    = (R - 100) / 0.385
```

以本次实测代表值 `pressure_raw=490980`、`temperature_raw=9514440` 粗略核对，可得到约 `0.005 kPa` 和 `27.85 ℃`。该压力式对应当前压力通道 PGA=16 的 STM32 配置；只能用于当前联调，不能替代正式标定。

学长上位机使用过另一套分段二次拟合系数。最终应由标定负责人确认：压力是表压还是绝压、量程、标准单位、零点定义、温补方法和正式标定参数版本。串口解析层不得把临时公式写死为不可更换的协议规则。

## 5. 已发现的三套阈值不一致

| 来源 | 压力/温度分界值 |
|---|---:|
| 当前 STM32 `main.c` | `8000000` |
| 学长 Qt 上位机 `ad_datacenter.cpp` | `2000000` |
| `ShuJvChuLi/serial_receiver.py` | `800000` |

当前静态状态下的压力约 49 万、温度约 951 万，所以三种阈值暂时都可能“看起来能用”。但压力升高后，`800000` 或 `2000000` 很可能把压力误判为温度。

处理要求：

- V0 兼容解析暂时以当前 STM32 源码中的 `8000000` 为准。
- 所有阈值必须只保留一处配置，不能散落在 UI、滤波器和数据库代码中。
- V1 协议必须彻底取消“通过数值大小猜通道”的做法。

## 6. 串口软件同学现在要完成的工作

### 6.1 建议模块结构

```text
SerialDeviceGateway
├─ SerialTransport
│  ├─ QSerialPortInfo 设备发现
│  ├─ 端口打开/关闭
│  ├─ 接收缓存
│  ├─ 发送队列
│  ├─ 超时与自动重连
│  └─ 连接统计
├─ ProtocolAutoDetector
│  ├─ V0 纯数字行识别
│  └─ V1 @PS1 结构化帧识别
├─ ProtocolCodecV0
│  ├─ 数字帧解析
│  ├─ 临时阈值分流
│  └─ 启动/调试/归零回复分类
├─ ProtocolCodecV1
│  ├─ 字段校验
│  ├─ CRC16 校验
│  ├─ 序号与丢帧统计
│  └─ 命令 ACK/NACK 匹配
└─ SampleMapper
   ├─ 原始码与状态映射
   ├─ 最新温度快照
   ├─ 标定/滤波服务入口
   └─ 对外统一 MeasurementSample
```

当前 Demo 中 `DeviceSimulator` 对 QML 暴露的属性和信号已经形成界面契约。推荐新增 `SerialDeviceGateway`，保持 `pressureKPa`、`temperature`、`connected`、`sampleReady(...)` 等外部接口不变，随后在 `main.cpp` 中按运行模式选择模拟器或真实网关，避免大面积修改 QML。

### 6.2 CMake 修改

当前工程只链接了 Quick、QuickControls2 和 Sql，需要增加 SerialPort：

```cmake
find_package(Qt6 6.4 REQUIRED COMPONENTS Quick QuickControls2 Sql SerialPort)

target_link_libraries(pressureos PRIVATE
    Qt6::Quick
    Qt6::QuickControls2
    Qt6::Sql
    Qt6::SerialPort
)
```

并把新建的串口网关、传输层、协议解析器和测试文件加入目标源文件列表。

### 6.3 端口发现与连接策略

1. 使用 `QSerialPortInfo::availablePorts()` 枚举端口。
2. 优先匹配：VID=`0x10C4`、PID=`0xEA60`、serial=`a83bd7f37698ef1197dfca63a8793231`。
3. 找不到完整序列号时，再使用配置文件中的 `/dev/serial/by-id/...`。
4. 最后才允许人工选择 `/dev/ttyUSB0`，并在界面明确提示这是易变路径。
5. 打开参数固定为 115200、Data8、NoParity、OneStop、NoFlowControl。
6. 串口对象必须只由一个线程和一个进程拥有。调试工具、学长上位机和 PressureOS 不能同时打开同一端口。
7. 端口拔出后不退出应用，按 1 s、2 s、5 s 上限循环重连；重连期间保留任务和数据库状态。
8. 重连成功后清空残留半帧，重新检测协议版本，并将“设备重新连接”写入审计/运行日志。

常用排查命令：

```bash
ls -l /dev/ttyUSB0 /dev/serial/by-id/*
fuser /dev/ttyUSB0
python3 -m serial.tools.miniterm /dev/ttyUSB0 115200
```

运行 `miniterm` 前必须先退出占用串口的 PressureOS。只读检查时不要按 `z` 或 `Z`。

### 6.4 必须正确处理半包和粘包

`QSerialPort::readyRead` 只代表“现在有若干字节”，不保证一次 `readAll()` 恰好得到完整一行。可能出现：

- 一次只收到数字的一半；
- 一次收到数行；
- `\r` 和 `\n` 分两次到达；
- 拔插时收到残缺帧。

必须保存跨回调的接收缓存，逻辑类似：

```cpp
rxBuffer += serial.readAll();

while (true) {
    const qsizetype newline = rxBuffer.indexOf('\n');
    if (newline < 0)
        break;

    QByteArray line = rxBuffer.left(newline);
    rxBuffer.remove(0, newline + 1);
    if (line.endsWith('\r'))
        line.chop(1);

    handleCompleteLine(line);
}

if (rxBuffer.size() > 256) {
    // 认为已失去帧同步，记录错误并清理到下一换行符
}
```

学长上位机目前采用 `readAll()` 后立即 `split('\n')`，但没有保留最后一个不完整片段，不能直接复制这一部分。

### 6.5 V0 解析规则

完整行按以下优先级处理：

1. 空行：忽略并计数。
2. `ID = 0x..`：记为设备启动/信息消息，不进入测量数据。
3. `Zero set!...`：记为旧版归零回复，不进入测量数据。
4. 纯十进制整数：转换为 `uint32`，检查 `0～16777215`。
5. `<8000000` 暂记为压力，`>=8000000` 暂记为温度。
6. 其他文本：记入诊断日志和 `parseErrorCount`，但接收线程继续运行。

V0 没有设备序号和设备时间，因此：

- 可以增加树莓派本地接收时间 `hostTimestampMs`；
- 可以增加本地递增计数，但必须标为 `hostFrameIndex`，不能伪装成下位机采样序号；
- 无法可靠区分“ADC 真正重复测得相同值”和“主循环重复读取旧寄存器”；
- 不要按“相同数值”简单去重，因为稳定压力下真实新样本也可能相同；
- 临时 Demo 可以按目标 UI 刷新率只保留最新值，例如 10～20 Hz，但原始接收统计应保留。

压力是主测量量。建议只有收到压力通道更新时才生成一条供数据库使用的统一样本，并附带最近一次温度；若温度超过约 2 秒未更新，应把温度标为 stale，而不是继续静默使用旧值。界面数值和曲线可独立节流，串口线程不得直接高频驱动 QML 重绘。

### 6.6 自动协议识别

建议配置项：

```text
protocolMode = auto | v0 | v1
```

`auto` 模式规则：

- 收到合法 `@PS1,...*CRC` 帧后，本次连接锁定为 V1；
- 只收到纯数字行时使用 V0；
- 重连后重新检测；
- V1 模式下仍可把未知文本记为诊断，但不能降级为按数值阈值分流。

这样嵌入式升级固件后，PressureOS 无需再次大改。

### 6.7 对外状态和统计

串口网关至少应提供：

```text

portName

lastFrameAgeMs
```

## 7. 嵌入式同学需要修改的内容

### 7.1 是否必须修改

分两个阶段：

- **今天要看到真实数据**：可以不改固件，树莓派用 V0 兼容解析接入。
- **正式测量、任务记录和项目验收**：必须修改固件。当前流无法证明每行都是新转换，也不能可靠识别通道或发现丢帧/错帧。

这次主要是固件修改，不要求修改现有 CP2102N、USB 连接和 USART1 硬件。

### 7.2 P0：正式接入前必须完成

1. **等待 DRDY**  
   每次上报前必须等待 AD7124 新转换完成；超时则上报状态/错误，不能继续把旧寄存器内容当新样本发送。

2. **读取真实通道状态**  
   不能再用 `<8000000` 猜通道。建议核对 AD7124 `DATA_STATUS` 配置，以一次 SPI 事务读取 24 bit 数据和附加状态字节，再从状态低位取得真实通道号。当前工程已有 `AD7124_8_GetCurrentChannel()`，但主循环未使用；当前 `AD7124_8_ReadADCData()` 只读取 3 字节，需要结合芯片手册确认并修改。

3. **只在形成一组新压力和新温度后发送测量帧**  
   分别保存本轮新压力码和新温度码，两者都更新后再发送一条 V1 `M` 帧。这样不会依赖数值阈值，树莓派也不会把两路数据重复计为两条压力样本。

4. **增加真实递增序号**  
   每形成一组新的有效测量数据，`sequence` 加 1。不得按串口打印次数递增。`uint32` 回绕属于正常情况。

5. **增加设备运行时间**  
   上报从 MCU 启动开始的 `uptime_ms`，建议 `uint32` 毫秒。树莓派同时记录接收时间，通过序号和设备时间检查卡顿、复位和丢帧。

6. **结构化区分测量、信息、ACK 和错误**  
   禁止再把无前缀的 `ID = ...`、`Zero set!...` 与测量值混在一起。所有输出都应使用 V1 消息类型。

7. **增加 CRC16**  
   每帧加入 CRC16/CCITT-FALSE。串口软件只允许 CRC 正确的 V1 测量帧进入正式数据链路。

8. **修正 LCD 刷新触发逻辑**  
   当前 `flag_adc % 10 == 0` 在计数保持为 10、20 等值时，温度分支不会递增该计数，可能在多次循环中反复执行 LCD 刷新并阻塞采样/发送。应改为独立定时刷新或一次性边沿触发，LCD 刷新不能决定采样节奏。

9. **明确实际采样率**  
   根据 AD7124 滤波器、双通道轮询和 LCD/计算耗时，实测并给出“每秒完整压力+温度数据组数”。不要把 UART 打印行速率当 ADC 输出数据率。

### 7.3 P1：强烈建议同时完成

1. 上电主动发送一次 `I` 设备信息帧，包含固件版本、MCU、ADC 型号、复位原因和状态。
2. 提供 `PING` 和 `GET_INFO` 命令，便于连接确认和诊断。
3. 定义 ADC 超时、SPI 错误、压力/温度无效、超量程、传感器故障、看门狗复位和安全锁存状态位。
4. 启用独立看门狗；MCU 重启后通过信息帧报告复位原因。
5. 将调试日志改为编译开关，正式版本不发送无协议前缀的文本。
6. 明确串口发送缓存策略，避免 `printf` 长时间阻塞采样主循环；必要时使用发送环形缓冲或 DMA。
7. 硬件超量程和安全保护必须在 MCU/硬接线层实现，不能等待树莓派发出切断命令后才保护。

### 7.4 归零功能必须重新定义

在正式实现 `ZERO` 前，嵌入式和测量负责人需先书面确认：

- 设备测量的是表压、绝压还是差压；
- 零点参考状态是什么；
- 归零时阀路/压力源应处于什么状态；
- 允许归零的压力和稳定性条件；
- 零点保存在 RAM 还是非易失存储；
- 断电后是否保留；
- 归零偏移的允许最大值；
- 是否由树莓派软件归零、MCU 归零，还是两者中只选一个作为权威。

最低实现要求：命令带 `cmd_id`；MCU 只使用明确的压力通道新样本；采集多点平均；异常时返回 NACK；相同 `cmd_id` 的重发不得重复执行；回复中返回偏移值和状态。未确认以上规则前，V1 可以先只实现 `PING`、`GET_INFO`，不开放 `ZERO`。

## 8. 建议冻结的 V1 文本协议

### 8.1 为什么先选结构化 ASCII

当前团队已经使用 `printf` 和逐行文本，结构化 ASCII 的改动量较小，串口抓包也能直接阅读。以当前数据率，文本开销对 115200 bit/s 足够。若后续进入更高采样率或多设备阶段，再评估二进制协议，不建议现在同时引入复杂转义和二进制调试成本。

### 8.2 通用帧结构

```text
@<payload>*<CRC16>\r\n
```

规则：

| 项目 | 定义 |
|---|---|
| 起始符 | `@` |
| 字段分隔 | 英文逗号 `,` |
| CRC 分隔 | `*` |
| 行结束 | `\r\n`；接收端可兼容单独 `\n` |
| 最大帧长 | 建议不超过 128 字节 |
| 字符集 | ASCII |
| 协议标识 | `PS1`，表示 PressureOS Serial Protocol V1 |
| CRC 范围 | `@` 之后、`*` 之前的全部 ASCII 字节，不包含 `@` 和 `*` |
| CRC 算法 | CRC-16/CCITT-FALSE |
| 多项式 | `0x1021` |
| 初始值 | `0xFFFF` |
| RefIn / RefOut | false / false |
| XorOut | `0x0000` |
| 输出格式 | 4 位大写十六进制 |

### 8.3 测量帧 M

```text
@PS1,M,<sequence>,<uptime_ms>,<pressure_adc>,<temperature_adc>,<status_flags>*<crc>\r\n
```

字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `PS1` | 固定文本 | 协议版本 |
| `M` | 固定文本 | Measurement |
| `sequence` | uint32 十进制 | 每组新压力+温度数据递增一次 |
| `uptime_ms` | uint32 十进制 | MCU 启动后毫秒数，允许回绕 |
| `pressure_adc` | uint32 十进制 | AIN13-AIN12 新压力原始码 |
| `temperature_adc` | uint32 十进制 | AIN5-AIN4 新温度原始码 |
| `status_flags` | 8 位十六进制 | 状态位，无 `0x` 前缀 |
| `crc` | 4 位十六进制 | CRC16 |

完整示例及正确 CRC：

```text
@PS1,M,1523,483920,490980,9514440,00000000*3EC2\r\n
```

### 8.4 设备信息帧 I

```text
@PS1,I,<sequence>,<uptime_ms>,<fw_version>,<device_id>,<adc_model>,<reset_reason>,<status_flags>*<crc>\r\n
```

示例：

```text
@PS1,I,0,125,1.0.0,STM32F103RC,AD7124-8,POR,00000000*27BD\r\n
```

字符串字段只允许字母、数字、点、下划线和连字符，不能包含逗号、星号、CR 或 LF。

### 8.5 命令帧 C

```text
@PS1,C,<cmd_id>,<command>[,<arg1>...]*<crc>\r\n
```

第一版建议命令：

| 命令 | 用途 | 是否有副作用 |
|---|---|---|
| `PING` | 测试双向链路 | 无 |
| `GET_INFO` | 请求设备信息帧 | 无 |
| `ZERO` | 执行正式零点校正 | 有；确认规则前禁用 |

示例：

```text
@PS1,C,42,PING*3527\r\n
@PS1,C,43,GET_INFO*4B8F\r\n
@PS1,C,44,ZERO*621A\r\n
```

### 8.6 ACK 与 NACK

成功回复：

```text
@PS1,A,<cmd_id>,<command>,OK,<result>,<status_flags>*<crc>\r\n
```

失败回复：

```text
@PS1,N,<cmd_id>,<command>,<error_code>,<status_flags>*<crc>\r\n
```

示例：

```text
@PS1,A,42,PING,OK,00000000*A5AA\r\n
@PS1,A,44,ZERO,OK,490980,00000000*110D\r\n
@PS1,N,44,ZERO,E_NOT_SAFE,00000004*1776\r\n
```

无副作用命令 ACK 超时建议初值为 500 ms，可重试最多 2 次。有副作用命令必须依赖 `cmd_id` 去重：MCU 收到已执行过的同一编号时返回缓存结果，不能再次执行。

### 8.7 建议状态位

| 位 | 掩码 | 含义 |
|---:|---:|---|
| 0 | `0x00000001` | ADC DRDY 超时 |
| 1 | `0x00000002` | ADC/SPI 通信错误 |
| 2 | `0x00000004` | 压力数据无效 |
| 3 | `0x00000008` | 温度数据无效 |
| 4 | `0x00000010` | 压力高于允许测量范围 |
| 5 | `0x00000020` | 压力低于允许测量范围 |
| 6 | `0x00000040` | 温度数据陈旧/未更新 |
| 7 | `0x00000080` | 传感器开路、短路或诊断故障 |
| 8 | `0x00000100` | 安全保护已经锁存 |
| 9 | `0x00000200` | 检测到看门狗/异常复位 |
| 10 | `0x00000400` | 配置或标定参数无效 |
| 11～31 | 保留 | 必须发送为 0，后续协议版本定义 |

实际无法立即检测的状态位可以暂时始终为 0，但嵌入式同学需要说明当前已实现哪些诊断，不能让上位机把未实现的诊断误认为“已验证正常”。

## 9. 通信状态与超时建议

V1 的实际完整数据组率需由嵌入式实测后冻结。软件初始建议：

| 条件 | 状态与处理 |
|---|---|
| 持续收到合法帧 | `streaming` |
| 超过正常周期 3～5 倍未收到新序号 | `degraded`，界面提示数据延迟，不继续把旧值当实时值 |
| 3 秒无合法帧或设备节点消失 | `disconnected`，停止正式记录并尝试重连 |
| CRC 错误 | 丢弃该帧，累计 `crcErrors` |
| 序号跳跃 | 接收后续帧，同时累计丢失数量并记录事件 |
| 序号倒退且伴随低 uptime | 判定 MCU 复位，重新读取 INFO |
| 单帧超过 128/256 字节仍无换行 | 认为失步，清理缓存并记录解析错误 |

数据库建议同时保存 `deviceTimestamp/uptime` 和 `hostReceiveTimestamp`，便于分析链路延迟和设备复位。

## 10. 联调步骤

### 阶段 A：当前固件 V0

1. 确认设备存在并且没有其他进程占用。
2. 串口同学使用只读抓取确认仍为 115200 8N1、纯数字 CRLF。

5. 暂不发送 `z`，暂不把当前固件行速率标为真实采样率。

### 阶段 B：嵌入式 V1

1. 嵌入式根据本文修改 DRDY、通道状态和帧输出。
2. 双方用固定测试字符串验证 CRC 实现；示例 `M` 帧必须得到 `3EC2`。

4. 核对序号连续、uptime 单调、每个 M 帧都包含一组新压力和新温度。
5. 模拟破坏 CRC、截断帧、粘连多帧，确认解析器行为。
6. 接入 PressureOS，并在设备诊断页显示协议版本和错误统计。

### 阶段 C：标定与正式数据

1. 由测量/标定负责人冻结压力类型、量程、分度值、零点和换算公式。
2. 标定参数写入树莓派数据库并带版本号，不在串口解析器中硬编码。
3. 对照标准压力源、STM32 原始码、学长上位机和 PressureOS 结果。
4. 再启用任务记录、拟合、不确定度和报告导出。
